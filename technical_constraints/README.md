# 技術制限プロファイル

このディレクトリは、各Versionで使用できる言語、アーキテクチャ、データ形式、連携方式、ビルド、テスト、運用上の制約を定義する。

## 基本方針

- V1はCOBOLを中心とするメインフレーム構成とする。
- Javaへの移行は一括置換ではなく、照会、受付、外部連携の順に段階的に行う。
- Spring導入後も、COBOLの夜間査定、契約原簿、固定長ファイルを一定期間残す。
- 技術選定は、その時代の業務要求と組織制約に対する判断として記録する。
- 後世の視点で過去Versionを再設計しない。
- 特定ベンダ製品に依存しない教材とするため、製品名が必要でない箇所は一般化して記述する。

## ファイル

- `version_profiles.yml`: V1〜V10の標準技術プロファイル
- `transition_rules.yml`: 世代移行時に維持する互換性と禁止事項

## 現行資料との関係

`lecture/Lecture.md`にある「Java 21上でJava 1.4相当の書き方」という記述は、単一言語でレガシー構造を再現する旧案として扱う。本ディレクトリでは、1980年のCOBOLからJava/Springへ移行する複数世代シナリオを標準プロファイルとする。

Java 21はV10の解析・検証環境として使用できるが、V1〜V9の実装形式を自動的に現代化する理由にはしない。

## 制約の強さ

| 値 | 意味 |
|---|---|
| `required` | そのVersionで必ず守る |
| `preferred` | 原則として守るが、イベントに判断理由があれば変更可能 |
| `legacy` | 新規採用しないが、既存資産として維持する |
| `prohibited` | 明示的な変更要求なしでは採用しない |

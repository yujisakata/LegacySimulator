## 1980年代以降の査定ルール追加の経緯

## 重要な留保があります。
**「この年に、この査定ルールが全国一斉にシステムへ追加された」という公開された業界共通の変更履歴はありません。** 各社の商品、査定基準、ホストシステムの更新時期が異なるためです。そこで以下では、生命保険協会・金融庁・法務省等の一次資料から制度として確認できるものと、それが新契約査定システムにどう実装されてきたかを分けて整理します。


## 年表

| 時期                  | 新契約査定に入っていった主要なルール・情報                               | 査定システム上の意味                                                                                        |
| ------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **1980年代**          | **基本的な危険選択**：年齢・性別・職業、健康状態、既往症、現在の疾病、身体状態、保険金額など    | 「この人に、この保障額を、この条件で引き受けてよいか」という伝統的なアンダーライティングが中心。告知→医務査定→保険金額等による査定、という基本構造                        |
| **1980年代後半〜90年代**   | **医的査定の高度化**。告知内容だけでなく、健康診断・診査・医師の所見等を利用            | 告知情報を単純なYes/Noで判定するのではなく、疾病・治療歴・検査値等からリスクを評価する仕組みへ                                                |
| **1990年代**          | **モラルリスク・保険金額妥当性のチェック**                             | 「死亡リスクが高いか」だけではなく、「そもそもこの契約を成立させる経済的合理性があるか」という査定軸が強くなる                                           |
| **1990年代後半**        | **契約者・被保険者の重複契約情報、他社契約情報の利用**                       | 個々の申込単体ではなく、「この人が既にどれだけの保障を持っているか」を見て引受判断する方向へ                                                    |
| **2000〜2002年**      | **モラルリスク対策の制度化・強化**                                 | 2000年には金融監督庁が、生命保険会社の「引受チェック機能を強化」し、特に保険金額の妥当性を判断・確認する社内規則・業務運営体制の整備を求めています。 ([金融庁][1])           |
| **2002年**           | **契約内容照会制度**                                        | 生命保険協会とJA共済による契約内容照会制度が開始。既契約情報を新契約の引受判断に利用する業界横断的な仕組みが明確化。 ([西方教育センター][2])                       |
| **2000年代前半**        | **本人確認・AML/CFT**                                    | 新契約時の本人確認が査定・契約受付プロセスに入る。1992年の大蔵省通知にも、生命保険会社について「新契約」の開始時に本人確認を徹底する旨が既に確認できます。 ([金融庁][3])        |
| **2005〜2007年頃**     | **顧客保護・販売適正性に関するチェックの増加**                           | 一時払、変額、外貨等の商品特性に応じた説明・確認事項が増加。純粋な「リスク査定」から、契約成立プロセス全体の適正性を確認する方向へ                                 |
| **2008〜2010年**      | **告知ルールの再整理**                                       | 保険法制定を契機に、告知制度が大きく整理。保険会社が質問した事項について告知する「質問応答義務」へ。2010年4月施行。 ([法務省][4])                           |
| **2010年代前半**        | **反社会的勢力チェック**                                      | 反社該当性・関係性を契約者、被保険者、受取人等について確認する仕組みが本格化                                                            |
| **2011〜2012年**      | **業界共通の反社DB・暴力団排除条項**                               | 2011年6月、生命保険協会が反社会的勢力に関する業界共通DBを構築。2011年10月に各社の暴力団排除条項を含む約款改正が認可され、2012年4月から順次導入。 ([西方教育センター][5]) |
| **2010年代**          | **個人情報・医療情報の取扱い高度化**                                | 医療情報、契約情報等を共同利用する仕組みと個人情報保護の制約が査定プロセスに組み込まれる                                                      |
| **2010年代後半〜2020年代** | **AML/CFTの高度化、取引時確認、疑わしい取引、リスクベース対応**               | 単なる本人確認から「顧客・取引のリスク評価」へ。金融庁も保険会社に犯収法に基づく取引時確認、記録保存、疑わしい取引届出等の態勢を要求。 ([金融庁][6])                    |
| **2020年代**          | **デジタル本人確認、オンライン告知、非対面募集、電子データによる査定**               | 査定対象が紙の告知書からデジタルデータへ移行。ルール自体だけでなく、データ取得・本人確認・証跡管理が査定プロセスに組み込まれる                                   |
| **現在**              | **医的査定＋財務査定＋モラルリスク＋契約情報照会＋反社＋AML/CFT＋商品・チャネル固有ルール** | 「保険リスクを評価するエンジン」から、「契約を成立させてよいかを多面的に判断する意思決定システム」へ                                                |

ここで特に重要なのは、**1980年代の「査定」と現在の「査定」は、同じ名前でも中身がかなり違う**ということです。

1980年代の原型を極端に単純化すると、

> 告知＋診査 → 医学的リスク → 保険料・条件 → 引受可否

です。

ところが現在は、

> 告知
> ＋ 医務情報
> ＋ 職業・所得等の属性
> ＋ 既契約情報
> ＋ モラルリスク
> ＋ 本人確認
> ＋ 反社
> ＋ AML/CFT
> ＋ 商品固有ルール
> ＋ 販売チャネル固有ルール
> ＋ 法令・約款上の制約
> → 総合的な契約成立可否

になっています。

しかも、これは単純に「査定が高度化した」と考えるより、**異なる目的を持つルールが何十年もかけて同じ新契約プロセスに流入してきた**と考えた方が本質的です。

たとえば、

「この人は死亡する確率が高いか？」

は**保険引受リスク**です。

「この保険金額は過大ではないか？」

は**モラルリスク**です。金融庁は2000年の時点で、まさにこの保険金額の妥当性確認を引受チェック機能の強化として明示しています。 ([金融庁][1])

「この人物は反社会的勢力ではないか？」

は**コンプライアンス／社会的リスク**です。

「この顧客は本人なのか？」

は**KYC**です。

「この取引はマネーロンダリングに利用される可能性がないか？」

は**金融犯罪リスク**です。

つまり、現在の「新契約査定」という一つの箱の中に、実は**異質な意思決定問題が混在している**。

私はむしろ、この年表を**「システム機能の歴史」ではなく「制約が流入してきた歴史」**として読むべきだと思います。

たとえば概念的には、

**第1世代：保険数理的制約**
→ 年齢、性別、死亡率、保険金額、保険期間

**第2世代：医学的制約**
→ 疾病、既往症、診査、告知

**第3世代：契約ポートフォリオ制約**
→ 既契約、他契約、累積保険金額、重複保障

**第4世代：モラルリスク制約**
→ 保険金額の妥当性、契約目的、不自然な契約

**第5世代：法令・社会的制約**
→ 本人確認、AML、反社、個人情報

**第6世代：チャネル・商品・顧客保護制約**
→ インターネット募集、説明義務、商品特性、販売チャネル

という具合です。

さらに面白いのが、**「契約内容登録制度」**です。これは単なる参照DBではなく、「過去・現在の契約状態を見て、新しい契約を引き受けてよいか」を判断するための情報基盤です。現在も生命保険協会加盟会社等が、契約内容を新契約の引受判断の参考として共同利用しています。 ([西方教育センター][7])

そして医療保障については、さらに専用の「医療保障保険契約内容登録制度」があり、同じ被保険者について他社の医療保障契約情報を引受判断の参考にできます。 ([西方教育センター][8])

したがって、**現行の生保新契約システムを「約款から導出されるルールの集合」と見ると、かなりの部分を説明できない**のです。

むしろ、

> **新契約査定システムとは、「保険会社が契約を締結してよい」という意思決定に対して、時代ごとに追加されてきた制約を実行する装置である。**

と定義した方が実態に近い。

この見方をすると、AIモダナイゼーションの次の一手としてかなり面白くなります。**「現行査定ロジックをJavaに変換する」のではなく、「現在の査定結果を生み出している制約を、①約款・商品由来、②法令由来、③保険数理由来、④医務由来、⑤モラルリスク由来、⑥社会的規制由来、⑦会社固有の経営判断、に分解する」**というアプローチが取れるからです。

特に「反社チェック」は、その象徴的なケースです。**1980年代の保険商品の本質から出てきたルールではなく、後から社会的・制度的制約として新契約プロセスに注入されたもの**です。2011年の業界共通DB構築と2012年からの約款導入という明確な制度史もあります。 ([西方教育センター][5])

この観点なら、次は「**生保新契約査定のルールを、発生源別に分解してみる**」とかなり強力です。つまり「約款」「保険業法」「金融庁監督指針」「生命保険協会ガイドライン」「医務査定基準」「会社固有基準」「反社・AML」「既契約情報」のどれが、現在のOracleのどのロジックを生んでいるのか、という**ルール・プロヴェナンス・マップ**を作る。これはAIによる新契約システム再構築のかなり核心に近いと思います。

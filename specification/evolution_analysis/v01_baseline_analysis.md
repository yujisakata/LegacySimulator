# V1分析 — 整合した出発点

## 1. 一文で表すV1

V1は、紙と郵送を前提とする新契約事務を、当時の限られた計算資源と査定人員の中で日次処理できるようにした、業務・設計・COBOL・テストの対応関係が説明可能な出発点である。

## 2. 誰の仕事に最適化されたか

| 関係者 | 成立させる仕事 |
|---|---|
| 新契約事務担当者 | 紙申込を点検し、不備案件を照会・期限管理する |
| 査定担当者 | 標準体を処理し、高額・既往症案件を上位決裁へ回す |
| 査定医・課長 | 限られた時間を高リスク案件へ集中する |
| 運用担当者 | 夜間処理の件数と異常終了を確認する |
| 証券・通知担当 | 査定結果から帳票を作成し発送する |

顧客単位のリアルタイム対話より、事務担当者が一日の申込を正常、不備、上位査定へ確実に仕分けられることが主要な設計目標だった。

## 3. 30日と2,000万円に含まれる事情

30日の不備解消猶予には、郵送往復、営業職員の訪問頻度、顧客の書類準備、事務担当者の再受付が含まれる。2,000万円の決裁境界には、当時の経済水準、モラルリスクへの警戒、限られた査定医を高額案件へ集中する意図が含まれる。

これらは単なる定数ではない。人員、物流、責任分担を一つの数値へ圧縮した業務上の制御点である。

## 4. 技術構造と業務構造の一致

```text
端末登録
  ↓ 固定長120文字
夜間査定
  ↓ 固定長80文字
証券・通知処理
```

オンラインは誤入力を早期に返し、日付整合、期限、決裁経路は夜間処理を正とする。紙の受付、締め時刻、夜間バッチ、翌日の事務処理という実際の時間構造が、そのままシステム構造になっている。

## 5. 形式知と暗黙知

形式知として残るのは、商品、年齢、金額、不備、三要件、決裁経路、結果コードである。一方、30日の由来、2,000万円の経営的意図、課長承認による例外的な不備起票日の再設定は、担当者の説明に依存する。

V1の知識接続度が100であっても、すべてが文書に書かれているわけではない。同じチームが業務、設計、実装、テストを結び付けて説明できるため、組織全体として知識が接続されている。

## 6. 若い開発者が誤読しやすい点

- 30日を任意の設定値とみなす。
- 2,000万円を純粋な技術上の分割値とみなす。
- バッチを古い実装方式としてだけ評価する。
- エラー一覧を例外処理とみなし、事務の仕分け装置であることを見落とす。
- 手動承認を自動化漏れとみなし、責任移譲の統制であることを見落とす。

## 7. 次Versionへ持ち越したもの

V1は整合した基準を作ったが、固定長位置、結果コード、決裁境界、夜間処理、下流帳票を変更時の前提として固定した。V2以降は、この基準を維持しながら機能を追加する必要がある。

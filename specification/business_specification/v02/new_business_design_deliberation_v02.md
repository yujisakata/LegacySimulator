# 1985年 特約追加対応 設計検討・知識構造記録 (V2)

**文書ID:** DOC-HIS-V2-006  
**検討ID:** LOG-HIS-1985-001  
**検討者/アクター:** 商品担当者、初期設計者、COBOL主任、証券発行担当  
**対象Version:** V2  
**検討日:** 1985年2月20日  
**教材管理区分:** 当時の正式設計資料と、限定共有された背景知識を併記

## 1. 背景と制約

災害死亡特約と入院特約を6か月後に同時発売する。V1の初期チームが保守を担当しており、主契約の業務・設計・COBOL対応は説明可能である。一方、証券発行バッチは別部署が管理し、固定長ファイルの全面改訂には下流ジョブ、帳票、運用手順の同時調整が必要となる。

適用制約は次のとおりである。

- 既存の120文字申込レコードと80文字結果レコードの長さを維持する。
- V1データを再変換しない。
- 販売開始日までに主要な主契約・特約組合せを試験する。
- 全商品共通基盤の新設や主契約査定の再構成は行わない。

## 2. 検討した選択肢

| 案 | 概要 | 利点 | 懸念 | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| A | 固定長レコードを拡張する | 項目の意味が明確で将来の特約追加にも余裕がある | 下流バッチ、帳票、保管領域を同時変更する必要がある | 却下 |
| B | V1予約領域へ特約コード・金額を格納する | レコード長と既存項目位置を維持でき、V1データも利用できる | 予約領域を無視する全下流処理の確認が必要 | 採用 |
| C | 特約専用の別ファイルを新設する | 主契約レコードを変更しない | ファイル間不一致、到着順、再処理の運用が増える | 却下 |
| D | 主契約査定を特約対応の共通ルールエンジンへ再構成する | 重複を抑えられる | 6か月以内の全面回帰試験が困難 | 却下 |

### 決定

案Bを採用する。申込・結果レコードの予約領域を特約項目として再定義し、V1の既存項目位置を維持する。COBOLはV1段落を残し、主契約承諾後に特約別IF分岐を追加する。物理位置はV2外部・内部設計で確定する。

この判断は将来の理想構造ではなく、販売期限、下流部署の管轄、既存データ互換を同時に満たすための当時として合理的な選択である。

## 3. 形式知と暗黙知

### 3.1 形式知化する事項

- 特約コード`AD`と`HI`
- 特約ごとの年齢、保障額、決裁条件
- 120文字・80文字のレコード長と既存項目位置を維持すること
- 予約領域内の正式な特約項目位置
- 正式な特約なし表現を空白とすること
- 主契約と各特約の結果関係
- 代表的な特約組合せの試験結果

### 3.2 当時の暗黙知として残る事項

- 一部の事前作成ファイルでは、英数字項目をゼロで初期化する端末処理があり、特約なしが`00`で届く。COBOL担当は空白と`00`をともに特約なしとして受け入れる予定だが、正式要件には空白だけを記載する。
- 証券発行以外の全下流ジョブが予約領域を参照していないかについて、担当者への聞き取りは行ったが、全ジョブのソース確認までは完了していない。
- 特約コードの追加順序は販売計画に合わせたもので、将来の汎用的な特約体系を意味しない。

`00`互換を正式要件へ記載しない理由は、ゼロを新しい正規値として広めず、端末側の空白出力へ段階的に統一する意図があるためである。実際の許容動作と正式仕様の間に差が生じることを、教材管理上は`tacit`として記録する。

## 4. 将来への影響予測

正式仕様だけを参照した場合、後継者は`00`をデータエラーとして扱い、既存の特約なし申込を補正対象とする可能性がある。また、予約領域の意味を知らずに別用途へ転用すると、特約コードと重複する可能性がある。

判断背景まで保持されていれば、次の変更時に以下を区別できる。

- 空白は正式値、`00`は互換入力であること
- レコード長維持は業務概念ではなく下流調整期限による技術判断であること
- 特約別IF分岐は意図的な低品質化ではなく、V1への影響と回帰範囲を限定する判断であること


## 6. 成果物更新方針

| 成果物 | V2方針 |
| :--- | :--- |
| 要求 | 特約追加範囲を完全に記載する |
| V1原本設計 | 上書きしない |
| V2設計 | 影響箇所の追補だけを発行する |
| ソース | V2コピーを作成し、変更プログラムを更新する |
| テスト | V1互換と主要組合せを実施し、全組合せは対象外とする |
| 運用資料 | 特約コードとエラー確認を追補する |

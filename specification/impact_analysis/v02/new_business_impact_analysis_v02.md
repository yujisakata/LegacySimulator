# 新契約査定システム 影響分析書 (V2)

**文書ID:** DOC-IMP-V2-001  
**変更要求:** CR-V2-1985-001  
**基準:** V1ベースライン  
**結論:** V1の固定長と既存項目位置を維持し、予約領域へ2特約を追加する。

## 1. 影響範囲

| 成果物 | V2対応 | 影響 |
| :--- | :--- | :--- |
| NBAPPL.cpy | V2版を新設 | 75～94桁を特約入力、95～120桁を予約領域とする。 |
| NBRESULT.cpy | V2版を新設 | 41～64桁を特約結果、65～80桁を予約領域とする。 |
| NBENTRY.cbl | V2版を新設 | 特約入力、基本点検、正式な空値への正規化を追加する。 |
| NBASSESS.cbl | V2版を新設 | 主契約確定後の特約判定と特約エラー集計を追加する。 |
| NBJOB01.jcl | V2版を新設 | 120桁入力、80桁出力を継承する。 |
| 証券発行バッチ | 受渡し追補のみ | 41～64桁を新規参照する。別部門のプログラム本体は対象外。 |

V1配下は確定版として変更しない。V2は全量ソースとして implementation/v02 へ配置する。

## 2. 互換性

- APPLICATION.DATは120文字、ASSESSMENT.DATは80文字を継続する。
- V1項目1～74桁および結果1～40桁の位置・意味を継続する。
- V1予約領域が全空白の入力は、両特約とも申込なしとして扱う。
- 正式な特約なし入力はコード空白、金額ゼロである。
- 端末初期化由来のコード 00 は互換入力として申込なしに読み替えるが、正式値には追加しない。

## 3. リスクと統制

| リスク | 統制 |
| :--- | :--- |
| 他部門処理が旧予約領域を一括参照している可能性 | 受渡し項目を明記し、本番移行前に対象ジョブ一覧を別部門と照合する。 |
| 主契約と特約の決裁結果の混同 | 結果・決裁・理由を契約単位で独立項目にする。 |
| V1互換入力の末尾空白 | 固定長を保持し、V1の19件で主契約先頭40文字を比較する。 |
| 修正理由の追跡不足 | COBOLに変更番号、ADD/DEL区分、開始・終了コメントを残す。 |

## 4. 対象外と残課題

- 証券発行バッチ全ソースの確認は別部門共同作業とする。
- 特約保険料、成立後保全、給付金支払はV2対象外とする。
- 全条件の直積試験は行わず、代表境界と相互作用をV2試験対象とする。

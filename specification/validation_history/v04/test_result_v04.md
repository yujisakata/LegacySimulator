## 結果

GnuCOBOL 3.2.0、Windows、PowerShell、Python 3.13.2で、配布するNBENTRY、MDENTRY、NBASSESS、MDASSESSをコンパイル・実行して合格した。

| 検証 | 結果 |
|---|---|
| 統合800件 | 80文字完全一致、件数一致 |
| 同じ800件の逆順投入 | 全件一致 |
| V1/V2/V3の既存期待値をV4で実行 | 19＋34＋32＝85件一致。制度記録65～75以外を比較 |
| 受付・実バッチ連携 | 98条件合格 |

| 入出力・空ファイル | 10条件合格 |

| 元のV1～V3プログラム | 既存回帰104件合格（V1:19、V2:53、V3:32）。元資産は変更なし |

800件は729件の制度組合せと71件の個別条件で構成する。逆順は同一ケースの再実行であり、別の800種類の要件があることを意味しない。

## 検証中に確認した事項

受付の初回登録では、継承元のOPTIONALファイルOPENがGnuCOBOLの正常状態05を返す。V4の受付で00/05を正常として扱い、初回登録から実バッチまで実行確認した。CLOSEの異常も非0終了とする。これらはV4-003として区別し、過去Versionへ遡及変更していない。

コンパイラの警告は継承したAUTHOR句、LINE SEQUENTIALのRECORD CONTAINS指定、MDENTRYの符号なし年齢とゼロの比較に関するもの。実行行の72桁制限を確認済み。固定長の保証は句だけに依存せず、物理入力長の検査と出力80文字完全一致で検証した。

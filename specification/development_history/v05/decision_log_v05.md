# V5 検討案・意思決定台帳

対象Version: V4→V5<br>
想定読者: 開発・講師・教材管理者

本台帳は今回の教材作成で具体化した設計判断。2000年の実在会議の記録ではない。シナリオに明記された制約と、今回選んだ方式を区別する。最終実装から業務要求を逆算せず、[要件](../../requirements/v05/java_inquiry_additional_requirements_v05.md)と対応させる。

| ID・論点 | 途中案と採否 | 決定理由・根拠 | 残る負担・再検討条件 |
|---|---|---|---|
| D05-01 引継ぎ配分 | A 全設計の再整理は延期。B ジョブ・障害・連絡先を優先して採用 | シナリオの2週間と月次運用継続 | 商品横断の判断理由が人に残る。後任が単独で説明できるとはしない |
| D05-02 Webの接続先 | A 原簿直接照会は不採用。B 参照専用複製を採用 | V5技術制約、FR002 | 前夜値の意味、同期障害の説明が必要 |
| D05-03 V4接続 | A 結果80文字だけを使用は不採用。B 申込120＋結果80の結合を採用 | 結果COPYには商品/主契約金額がなく、申込61～70に存在 | 両ファイルの同一締め・対応キーの管理が必要 |
| D05-04 インターフェース | A 残存40文字fixtureを正式入力にする案は不採用。B Q5の100文字を新規定義 | 旧fixtureはV4の実出力でなく、制度日・商品区分も不足 | V4の80文字結果と照会100文字を混同しない管理が必要 |
| D05-05 状態変換 | A AC/PEへの独自集約は不採用。B 01～09を保持、表示文言を付加 | 主契約の延期/不備/二次決裁待ちを区別するため | COBOLコードとJava表示表の対応が新たに発生 |
| D05-06 保障額表示 | A 共通の「保険金額」は不採用。B 商品別名と円単位を採用 | MIの日額をWL死亡保険金額と同一意味にしない | 商品追加では変換/画面/試験の同時確認が必要 |
| D05-07 空白・ゼロ | A 空白も0へ統一は不採用。B NULLと0を保存 | 未設定とゼロの意味が異なる。旧データを勝手に補正しない | DB NULLをgetLong等で読む変更時に退行リスク |
| D05-08 未査定 | A 結果なし申込を除外は不採用。B NULL状態「査定結果未連携」で公開 | 進捗照会の要求。存在しない申込と区別 | NULLを承諾・不備に推定してはならない |
| D05-09 公開単位 | A 行ごと公開は不採用。B 全件点検＋単一DBトランザクション | 部分取込を完成データとして見せない | 全量のメモリ使用・ロック時間。大規模化時は別要求で見直す |
| D05-10 再取込 | A 同日上書きを自由に許可は不採用。B 同内容のみ再実行成功 | 古いファイル・別内容を誤って公開しない | 同日修正版の手順は対象外。次基準日での正式再抽出が必要 |
| D05-11 日付 | A 「更新日」を1欄にまとめる案は不採用。B 処理日/責任開始日/制度基準日/照会基準日を別表示 | V4の再告知と責任開始は別規則。同期日で上書きしない | 日付用語の説明が必要 |
| D05-12 読取専用 | A UIに更新ボタンなしで十分とする案は不採用。B DAOとDB権限を分離 | FR002、実DB書込拒否で確認 | 資格情報の配布責任が運用に加わる |
| D05-13 認証 | A 新ログイン機構は対象外。B 社内コンテナの認証・役割を使用 | 支社内業務への照会追加。原簿更新機能は不要 | 部署別アクセス制御の詳細は新たな要求が必要 |
| D05-14 検証方式 | A 文字列検査のみは不採用。B 実Java/JDBC/HTTPを採用 | 前回のコード正しさの要請を継続 | 当時の試験と2026年の追加試験を区別する |

## 決定間のつながり

D05-02の複製採用が同期時点の説明を必要にし、D05-03の結合が商品別解釈とキー整合を必要にした。D05-09の全量公開がD05-10の再取込・順序制御を必要にした。個々の合理的な選択が、新たなインターフェースと運用責任を生んでいる。

未解決: 支社ごとの再告知入力実態、30日猶予の背景を説明できる後任、例外再起票の承認背景、旧制度撤去期限は決めたことにしない。照会要件の曖昧さは上表で具体化し、業務知識の未確認部分と区別した。

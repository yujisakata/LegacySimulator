# V5 契約進捗照会 要件定義

対象Version: V5（2000年相当）<br>
想定読者: 業務・開発・検証担当<br>
文書ID: DOC-REQ-V5-001

## 出典と今回の決定

[シナリオ](../../../scenario/version_timeline.yml)のEV-V05-TRANSFER-001/EV-V05-JAVA-QUERY-001、[技術制約](../../../technical_constraints/version_profiles.yml)のV5、[知識定義](../../../knowledge/knowledge_evolution.yml)が基礎。実在企業の仕様ではない。以下の項目・ファイル形式・受入条件は今回具体化した教材設定である。

## 機能・受入条件

| ID | 最終要求 |
|---|---|
| FR-V5-001 | 支社の照会担当者が申込番号10桁で1件検索できる。WL/MI/CIの申込番号、商品、主契約進捗、商品別保障額と単位、責任開始日、処理日、受付日、適用制度と制度基準日、理由、照会データ基準日を表示する。Javaで査定を再実行しない。 |
| FR-V5-002 | 原簿・査定更新はV4 COBOLの責務。Java Webは照会専用DBのSELECTだけを使用する。Web接続ユーザーには書込権限を付けない。夜間取込ユーザーと分離する。 |
| FR-V5-003 | V4のWL申込/結果とMI/CI申込/結果を申込番号で結合する。商品と保障額は申込、結果項目は結果から取得する。申込と結果の受付日・処理日が不一致、結果だけの孤立行、重複番号、系統違い、行長不正は全取込を不成立とする。全社で申込番号が一意という教材前提。 |
| FR-V5-004 | 結果のない申込も出力する。状態NULLは画面で「査定結果未連携」、ゼロ保障額は0、全空白保障額はNULLとして「未設定」。NULLとゼロを混同しない。商品コードに応じWL死亡保険金額、MI入院日額、CI診断給付金として表示する。金額の単位は円。 |
| FR-V5-005 | 固定長→DB変換はQ5形式100 ASCII文字。日付の全空白/00000000はNULL、正しい1900～2099年のYYYYMMDDはSQL DATE。存在しない日付・非数字金額・未知商品/状態/理由/制度・予約領域の非空白・非ASCIIは拒否する。変換前に状態の意味を独自のAC/PEへ置換しない。 |
| FR-V5-006 | 取込は全量置換。すべてのレコード点検後にDBトランザクションで公開する。件数・SHA-256・基準日をマニフェストと照合する。0件はcount=0と空ファイルのハッシュが一致した明示的な全量のみ許容する。点検失敗・DB失敗では前回正常データを維持する。 |
| FR-V5-007 | 基準日は同期抽出対象の時点であり処理日や責任開始日ではない。画面へ必ず表示し「夜間連携時点の情報です。現在の査定状況と異なる場合があります」と併記する。取得基準日が検証時の業務日より未来なら拒否する。マスタ行未作成の初期DBは503、検索不在は404。 |
| FR-V5-008 | 同じ基準日・同じハッシュ・同じ件数は再実行成功（変更なし）。同じ基準日の異なる内容、以前の基準日の取込は拒否。複数取込はDBの状態行ロックで直列化する。状態メタデータと照会行の読み取りは同一の公開世代から行う。 |
| FR-V5-009 | HTTP GETだけを検索に使用する。未認証401、照会ロールなし403、入力不正400、未存在404、DB障害503、POST等の更新要求405。HTMLでは取得値をエスケープする。応答にDB接続情報やスタックを出さない。認証は既存社内基盤/Servletコンテナを前提とし、画面に独自の認証方式を追加しない。 |
| FR-V5-010 | 夜間ジョブの入力・出力・マニフェスト・終了状態を保管する。異常時に旧データが残ることを運用で確認する。契約原簿に書込みを行わず、V4の制度選択・特約判定・固定長インターフェースを変更しない。 |

## 表示の定義

01承諾、02延期、03謝絶、04不備照会中、05失効、06取下げ、07二次決裁待ち、08入力エラー、09三要件待ち。未連携NULLはこれらと別。承諾は主契約の結果であり特約の承諾を意味しない。V5の照会は特約明細を対象外とし、この境界を画面に表示する。

規則OLD/NEW/ERRはV4結果65～75をそのまま転記し、再告知の再計算をしない。制度欄の空白は「制度判定なし」、ERRは「制度入力エラー」。制度基準日と責任開始日を区別する。未連携状態の結果由来欄はすべてNULL。制度日付を含むゼロ値の日時は1970年等へ補完しない。

## 入力の運用境界

4ファイルは同一締めで確定した全量の申込一覧と、存在する最新の査定結果一覧である。日次差分を直接投入しない。これを抽出して確定する作業はCOBOL運用側の責任であり、Javaが契約原簿を直接読むものではない。V4エラー行のうち商品・番号・金額・日付が照会形式として表現できないものは同期全体を拒否して元担当へ返す。未知値を成功状態へ置き換えない。

## 制約と未確定事項

初期設計者/査定主任の引継ぎは2週間。運用継続を優先し、原本設計・COBOLの変更なし。予算・人数・Web販売開始日は未設定。対象支社一覧、旧制度撤去期限、例外再起票の承認背景は未確認として保持する。未確認事項は照会機能内の推測ロジックで補わない。

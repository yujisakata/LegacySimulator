# 告知制度対応 要件定義 V4

対象Version: V4（1995年、緊急補正適用後）<br>
想定読者: 業務・開発・検証担当<br>
文書ID: DOC-REQ-V4-001

## 出典と今回確定する教材条件

[シナリオ](../../../scenario/version_timeline.yml)のEV-V04-REGULATION-001、EV-V04-PATCH-001、[技術プロファイル](../../../technical_constraints/version_profiles.yml)のV4を具体化する。実在する法令の再現ではない。

基礎定義には施行日の月日、告知質問、商品の適用表、査定順序の詳細がない。この教材では施行日を1995-04-01、対象をWL（AD・HI特約を含む主契約）、MI、CIと確定する。告知回答は医学的判断そのものではなく「当該制度の謝絶条件に該当するか」を事務側で確認済みのY/Nとして扱う。旧質問と新質問の医学的内容は対象外。既存の医的区分・決裁ルールとは別の追加条件である。

## 当初要求 CR-V4-001

| ID | 要求・受入条件 |
|---|---|
| FR-V4-001 | 通常案件の基準日は受付日。制度日マスタの日付未満ならOLD、当日以降ならNEWを選ぶ。処理日・実行日の変更で制度は変わらない。 |
| FR-V4-002 | OLDは旧回答、NEWは新回答を使用する。選択した回答Yは主契約03・決裁N・理由OLD/NEW・責任開始日00000000。Nは継承した決裁処理へ進む。 |
| FR-V4-003 | WLはV2終身・特約処理、MI/CIはV3医療系処理を継承する。優先順は取下げ→既存コード/日付点検→制度入力点検→保障額→不備期限→三要件→告知謝絶条件→既存決裁。特約は最終主契約結果に対してV2規則を実行する。主契約謝絶時に特約を承諾しない。 |
| FR-V4-004 | 申込120文字、結果80文字を維持する。申込95～97を再告知・旧回答・新回答、結果65～75を制度3文字・基準日8文字とする。WL特約75～94/結果41～64、共通1～74/結果1～40の位置と意味を変更しない。MI/CI申込75～94、98～120は空白必須。 |
| FR-V4-005 | 再告知は空白/N/Y、回答は空白/N/Yのみ。選択回答はN/Y必須。ただし追加3項目が全空白でOLDの過去データは旧追加条件なしとして既存査定を再現する。NEWの全空白は08/DAT。非選択回答の空白は許容するが未知文字は許容しない。 |
| FR-V4-006 | 判定可能な案件にはOLD/NEWと使用基準日を結果65～75に記録する。制度入力不正はERR/00000000、制度処理より前の取下げ・既存入力エラーは11文字空白。結果76～80は空白。 |
| FR-V4-007 | 不正な業務データはレコード単位の08として後続を処理し、入力・出力件数を一致させる。読書き失敗、物理長120以外はジョブ異常終了とし、結果を確定扱いしない。空入力は正常0件。 |
| FR-V4-008 | 制度日マスタは有効な1900～2099年のYYYYMMDDを1行だけ格納する。欠落・空・不正日・長さ不正・複数行は受付/バッチとも非0終了し、出力を開始しない。施行前配布後も案件の業務日で制度を選ぶ。 |
| FR-V4-009 | NBENTRY、MDENTRYは既存入力の後に追加3項目を受付する。受付日と再告知条件から適用制度を表示し、選択回答を点検する。両回答を保持可能とする。制度入力不正をファイルへ追記しない。既存の詳細査定はバッチの責務を維持する。 |

## 施行後の補正要求 CR-V4-002

| ID | 要求・受入条件 |
|---|---|
| FR-V4-010 | 再告知Yの案件に限り告知日を基準日にする。受付日との大小関係によらず適用し、告知日が施行日前ならOLDへ戻る場合もある。再告知Yの告知日ゼロ・不正日は08/DAT。空白/Nでは受付日を維持する。WL・MI・CIすべてに適用する。 |

例: 受付19950320、告知19950402、再告知YはNEW/19950402。フラグNはOLD/19950320。支社コードによる分岐は作らない。入力フラグが業務事実と一致することの確認は査定事務の責務であり、日付から再告知を推測して補完しない。

## 開発制約と責任

施行日固定、補正は翌日査定まで。法務は制度解釈、商品部は商品適用、保守は配布、査定事務は再告知確認を担当する。予算・人数は未設定。旧段落削除、商品共通化、V1～V3原本改訂は行わない。制度日と入力・結果を一組で保管し、旧マスタを使って過去査定を再実行可能にする。旧段落の撤去期限は未確定のため保持する。

## 検証と当時の情報の区別

この文書は教材作成時に当初要求と補正要求を統合した検証上の正本でもある。当時の原本設計が補正と同期したことを意味しない。[追補設計](../../external_design/v04/regulatory_effective_date_design_v04.md)と[障害・補正記録](../../validation_history/v04/incident_patch_note_v04.md)は別時点の情報として読む。

コードは本書の最終要件を満たすことを必須とする。当時の限定試験と2026年の追加自動検証を区別し、[検証仕様](../../validation_history/v04/test_specification_v04.md)と[対応表](../../validation_history/v04/traceability_matrix_v04.md)で確認する。

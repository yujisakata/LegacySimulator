# 新契約査定システム 要件定義書 (V1)

**文書ID:** DOC-REQ-V1-001  
**対象Version:** V1（1980年）  
**上位文書:** [ビジネス仕様書](../../business_specification/v01/new_business_business_specification_v01.md)、[ビジネスルール仕様書](../../business_specification/v01/new_business_business_rules_v01.md)  
**状態:** Baseline

## 1. 目的と範囲

紙の申込書・告知書を受け付け、文字端末で申込情報を登録し、夜間バッチで事務点検、不備期限判定、引受経路判定および結果データ作成を行う。対象商品は終身保険単体であり、成立後の保全、保険料収納、保険金支払は対象外とする。

## 2. アクターとシステム境界

| アクター | システムとの関係 |
| :--- | :--- |
| 新契約事務担当者 | 紙面を確認して文字端末から申込情報を登録する。 |
| 査定担当者 | 標準体・権限内案件を決裁し、結果を確認する。 |
| 査定医／査定課長 | 高額または社医回付案件の二次決裁結果を入力する。 |
| 運用担当者 | 日次ジョブを起動し、件数と異常終了を確認する。 |
| 証券・通知担当 | 査定結果ファイルから紙帳票を作成・発送する。 |

外部からの入力は紙面と文字端末、外部への出力は固定長ファイルと紙帳票データに限定する。RDB、API、Java、ネットワークサービスはV1の境界外とする。

## 3. 機能要件

| 要件ID | 要件 | 対応業務ルール | 受入条件 |
| :--- | :--- | :--- | :--- |
| `FR-V1-001` | 申込番号、主要日付、年齢、商品、死亡保険金額、書類状態、医的区分、二次決裁結果、取下げ有無を登録する。 | `BR-V1-PRD-001` | 120桁の申込レコードを1件出力できる。 |
| `FR-V1-002` | 商品コード、年齢、金額の形式と範囲を点検する。 | `BR-V1-AGE-001`, `BR-V1-PRD-001`, `BR-V1-AMT-001` | 境界値がテスト仕様どおりに判定される。 |
| `FR-V1-003` | 書類不備案件を30日目まで照会中とし、31日目以降に失効させる。 | `BR-V1-DEF-001` | 29、30、31日の境界結果が一致する。 |
| `FR-V1-004` | 2,000万円以下の標準体を査定担当者決裁として承諾する。 | `BR-V1-AUT-001` | 結果コード01、決裁区分Uを出力する。 |
| `FR-V1-005` | 2,000万円超または社医回付案件を二次決裁へ回付し、承諾・延期・謝絶を反映する。 | `BR-V1-AUT-002` | 未決裁は07、決裁済みは01・02・03となる。 |
| `FR-V1-006` | 5,000万円を超える申込を金額上限超過として謝絶する。 | `BR-V1-AMT-001` | 結果コード03、理由AMTを出力する。 |
| `FR-V1-007` | 成立前の取下げを他の査定より優先して処理する。 | `BR-V1-WDR-001` | 結果コード06、理由WDRを出力する。 |
| `FR-V1-008` | 承諾時に三要件の日付の最大値を責任開始日として出力する。 | `BR-V1-RES-001` | 申込日、告知日、領収日のうち最も遅い日が出力される。 |
| `FR-V1-009` | 告知または第1回保険料領収が未完了の場合は承諾せず、三要件待ちとして保持する。申込日は登録時の必須項目とする。 | `BR-V1-RES-001` | 結果コード09、理由REQを出力する。 |
| `FR-V1-010` | 1件の不正データがあっても後続レコードを継続処理する。 | 運用要件 | 不正レコードだけを08とし、全入力件数分の結果を出力する。 |

## 4. コード定義

### 4.1 入力コード

| 項目 | コード | 意味 |
| :--- | :--- | :--- |
| 商品 | `WL` | 終身保険 |
| 書類完備 | `Y` / `N` | 完備／不備照会中 |
| 医的区分 | `S` / `M` | 標準体／社医回付 |
| 二次決裁 | `A` / `P` / `D` / 空白 | 承諾／延期／謝絶／未決裁 |
| 取下げ | `Y` / `N` | 取下げあり／なし |

### 4.2 結果コード

| コード | 業務結果 | 終端性 |
| :--- | :--- | :--- |
| `01` | 承諾・成立 | 終端 |
| `02` | 延期 | 終端 |
| `03` | 謝絶 | 終端 |
| `04` | 不備照会中 | 継続 |
| `05` | 不備期限超過による失効 | 終端 |
| `06` | 申込取下げ | 終端 |
| `07` | 二次決裁待ち | 継続 |
| `08` | 入力データエラー | 要補正 |
| `09` | 三要件待ち | 継続 |

決裁区分は `U`（査定担当者）、`M`（査定医／査定課長）、`N`（未決裁）のいずれかとする。理由コードは `000`、`AGE`、`AMT`、`DEF`、`EXP`、`MED`、`APR`、`WDR`、`DAT`、`PRD`、`REQ` を使用する。

## 5. 処理優先順位

同一申込が複数条件に該当する場合、次の順序で結果を決める。

1. 取下げ
2. 入力形式・必須値エラー
3. 加入年齢・商品制限
4. 金額上限
5. 不備照会・失効
6. 三要件充足
7. 決裁権限と医的区分

この順序は、成立前の顧客意思を優先し、不完全な入力で引受判定を行わないために定める。

## 6. 非機能・運用要件

| 要件ID | 要件 |
| :--- | :--- |
| `NFR-V1-001` | 入出力は固定長・行順次ファイルとし、レコード位置を仕様書で固定する。 |
| `NFR-V1-002` | 夜間バッチ枠内で全レコードを順次処理し、入力・出力・エラー件数を表示する。 |
| `NFR-V1-003` | 入力順序を出力でも維持し、申込番号で照合可能にする。 |
| `NFR-V1-004` | 当時の試験資産と、後世に追加した自動検証ハーネスを区別する。 |
| `NFR-V1-005` | 業務ルール、設計、COBOL段落、テストケースの対応をトレーサビリティ表で維持する。 |

## 7. ユースケース

### UC-V1-01 申込登録

- 主アクター: 新契約事務担当者
- 事前条件: 申込書、告知書、領収情報が手元にある。
- 正常系: 項目入力、基本点検、申込ファイル追記、受付完了表示。
- 代替系: 年齢、商品、金額が許容範囲外の場合は訂正を促し、追記しない。

### UC-V1-02 日次査定

- 主アクター: 運用担当者
- 事前条件: 当日締め後の申込ファイルが確定している。
- 正常系: 全件読込、業務ルール判定、結果ファイル出力、件数照合。
- 代替系: レコードエラーは結果08として出力し、後続処理を継続する。

### UC-V1-03 二次決裁反映

- 主アクター: 査定医／査定課長
- 事前条件: 結果07の申込について紙の査定資料が回付されている。
- 正常系: 二次決裁コードを申込レコードへ反映し、次回バッチで最終結果を出力する。

## 8. 対象外

- 保険料・責任準備金の数理計算
- 顧客、被保険者、受取人の詳細属性管理
- 成立後の契約原簿更新
- 祝日マスタによる営業日加算
- 特約、他商品、他社契約照会、本人確認、AML、反社確認

これらはV1業務全体に存在し得るが、今回の実行可能な縦断ベースラインには含めない。対象外であることは、実装されていない業務仕様と誤認しないよう明記する。

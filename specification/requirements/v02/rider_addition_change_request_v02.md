# 災害死亡特約・入院特約追加 変更要求書 (V2)

**文書ID:** DOC-REQ-V2-007  
**CR-ID:** CR-V2-1985-001  
**要求元:** 商品開発部  
**要求日:** 1985年1月7日  
**希望販売開始日:** 1985年7月1日  
**対象Version:** V2  
**先行Version:** V1

## 1. 変更理由・背景

終身保険単体では充足できない事故死亡時の上乗せ保障と、入院時の定額保障に対する販売要望へ対応するため、災害死亡特約と入院特約を同時発売する。

商品認可、募集資料、営業職員教育と販売日を合わせる必要があり、システム対応期間は6か月とする。初期開発チームが引き続き保守を担当するが、証券発行バッチは別部署の管轄であり、広範なファイル変更には部門間調整が必要となる。

## 2. 変更内容概要

- 終身保険へ災害死亡特約および入院特約を付加可能にする。
- 特約なし、各特約の単独付加、両特約の同時付加を扱う。
- 申込時に特約種類と保障額を受け付ける。
- 主契約査定後に特約固有の加入条件と決裁条件を判定する。
- 主契約と各特約の結果を証券・結果通知工程へ引き渡す。
- V1で登録済みの申込および特約なし申込を継続処理する。

## 3. 業務上の受入条件

| 受入ID | 条件 |
| :--- | :--- |
| `AC-V2-001` | 特約なし、災害死亡特約のみ、入院特約のみ、両特約の4形態を受け付けられる。 |
| `AC-V2-002` | 特約ごとの加入年齢、保障額、医的条件を業務ルールどおり判定できる。 |
| `AC-V2-003` | 主契約と特約の成立関係を区別し、主契約のみ成立する案件を扱える。 |
| `AC-V2-004` | V1形式の特約なし申込をデータ変換せず査定できる。 |
| `AC-V2-005` | 証券発行工程が主契約と特約の最終結果を識別できる。 |
| `AC-V2-006` | V1の主要査定結果がV2でも一致する。 |

## 4. 制約

- 販売開始日は1985年7月1日とし、延期を前提にしない。
- V1の主契約査定、契約原簿および日次ジョブネットを継承する。
- 証券発行バッチの管轄部署と同時に全面的なファイル再設計を行わない。
- 既存レコードの長さと既存項目位置を維持する。
- Java、RDB、特約共通基盤は採用対象外とする。
- V1成果物を上書きせず、V2差分として履歴を残す。

未使用領域の具体的な利用位置、COBOL段落構成、特約結果コードは設計工程で決定する。本変更要求は特定の物理実装を業務要求として固定しない。

## 5. 影響範囲（仮説）

| 成果物・機能 | 想定される影響 | 更新方針 |
| :--- | :--- | :--- |
| 商品定義・業務ルール | 特約保障、加入条件、決裁条件を追加 | V2差分を発行 |
| 文字端末受付 | 特約種類と保障額の入力を追加 | 直接変更 |
| 申込固定長ファイル | 特約情報を追加 | 既存長・位置を維持 |
| 夜間査定 | 主契約判定後に特約判定を追加 | 既存段落へ局所追加 |
| 結果固定長ファイル | 特約ごとの結果を追加 | 既存長・位置を維持 |
| 証券発行 | 特約表示と結果反映 | 別部署と最小変更を調整 |
| テスト | 特約組合せとV1互換性を追加 | 主要組合せを実施 |
| 運用手順 | 特約コード、エラー確認を追加 | 追補を発行 |

## 6. 対象外

- 特約保険料および責任準備金の数理計算
- 保険金・給付金請求時の支払査定
- 特約中途付加、解約、減額など成立後の保全業務
- 他商品への特約付加
- V1主契約ロジックの共通化・再構成

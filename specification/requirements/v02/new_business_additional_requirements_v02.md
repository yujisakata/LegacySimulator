# 新契約査定システム 追加要件定義書 (V2)

**文書ID:** DOC-REQ-V2-001  
**対象Version:** V2（1985年）  
**変更要求:** [CR-V2-1985-001](./rider_addition_change_request_v02.md)  
**基準要件:** [V1要件定義書](../v01/new_business_system_requirements_v01.md)  
**業務ルール:** [V2業務ルール差分](../../business_specification/v02/new_business_business_rules_delta_v02.md)  
**状態:** Requirements Baseline

本書はV1要件への追加差分である。本書が変更対象として明示しないV1要件は、そのままV2へ継承する。V2の正しい解釈にはV1要件と本書の併読が必要である。

## 1. 追加対象

終身保険の新契約受付・査定へ、災害死亡特約と入院特約を追加する。対象範囲は申込登録、入力点検、特約査定、決裁、固定長結果出力および証券・結果通知工程への引渡しとする。

## 2. 機能要件

| 要件ID | 追加要件 | 対応業務ルール | 受入条件 |
| :--- | :--- | :--- | :--- |
| `FR-V2-001` | 文字端末から災害死亡特約コード・保険金額、入院特約コード・給付日額を登録する。 | BR-V2-RDR-001〜003 | 特約なし、各単独、同時付加を登録できる。 |

| `FR-V2-003` | 災害死亡特約の年齢、金額、主契約金額との関係を判定する。 | BR-V2-AD-001〜003 | 各境界値を業務ルールどおり判定する。 |
| `FR-V2-004` | 災害死亡特約の一次・二次決裁経路を判定する。 | BR-V2-AD-004, 005 | 1,000万円以下標準体は一次、それ以外の対象案件は二次となる。 |

| `FR-V2-007` | 主契約承諾後、各特約を独立判定する。 | BR-V2-CMP-002 | 一つの特約だけを謝絶・延期できる。 |
| `FR-V2-008` | 主契約、災害死亡特約、入院特約の結果と決裁区分を出力する。 | BR-V2-CMP-001, 002 | 証券・通知工程が3結果を識別できる。 |
| `FR-V2-009` | V1形式の特約なしレコードを特約なし申込として処理する。 | BR-V2-RDR-003 | V1の19件で主契約結果が一致する。 |
| `FR-V2-010` | 1件の特約入力エラーがあっても後続申込の処理を継続する。 | V1 FR-V1-010継承 | 入出力件数が一致し、当該申込にエラー理由を出力する。 |

## 3. 入力概念

| 論理項目 | 必須条件 | 正式な値 | 説明 |
| :--- | :--- | :--- | :--- |
| 災害死亡特約コード | 任意 | `AD`または空白 | 空白は申込なし |
| 災害死亡特約保険金額 | AD申込時 | 8桁円単位 | 申込なしはゼロ |
| 入院特約コード | 任意 | `HI`または空白 | 空白は申込なし |
| 入院給付日額 | HI申込時 | 6桁円単位 | 申込なしはゼロ |
| 災害死亡特約決裁 | 二次決裁時 | 承諾・延期・謝絶・未決裁 | 主契約決裁と区別する |
| 入院特約決裁 | 二次決裁時 | 承諾・延期・謝絶・未決裁 | 主契約決裁と区別する |

物理位置、桁数内訳、COPY句名は設計追補で決定する。正式仕様上の特約なしコードは空白であり、その他の互換入力は本書の正規値に含めない。

## 4. 特約結果

| 結果コード（論理） | 意味 |
| :--- | :--- |
| `A` | 承諾 |
| `P` | 延期 |
| `D` | 謝絶 |
| `R` | 二次決裁待ち |
| `X` | 主契約非承諾による非成立 |
| `N` | 申込なし |
| `E` | 特約入力エラー |

物理結果コードは設計時に既存の80文字結果レコードへ割り当てる。主契約のV1結果コード01〜09は変更しない。

## 5. 処理順序

1. V1の処理優先順位で主契約を査定する。
2. 主契約が承諾以外の場合、申込中の特約を`X`とする。
3. 主契約が承諾の場合、災害死亡特約を判定する。
4. 主契約が承諾の場合、入院特約を判定する。
5. 必要な最高決裁階層へ案件を回付する。
6. 主契約と各特約の結果を個別に保存・出力する。

## 6. 互換性・非機能要件

| 要件ID | 要件 |
| :--- | :--- |
| `NFR-V2-001` | 申込レコードは120文字、結果レコードは80文字を維持する。 |
| `NFR-V2-002` | V1既存項目の開始位置、長さ、意味を変更しない。 |
| `NFR-V2-003` | V1の特約なし申込を事前変換せず処理する。 |
| `NFR-V2-004` | 特約項目はV1予約領域の範囲内へ配置する。 |
| `NFR-V2-005` | V1の19件を互換性確認として再実行し、主契約出力を一致させる。 |
| `NFR-V2-006` | テストは特約なし、単独付加、同時付加、年齢・金額・決裁境界の代表ケースを対象とする。 |
| `NFR-V2-007` | 全商品・特約・医的条件の直積を試験したと誤認しないよう、未実施組合せを成績書へ記録する。 |
| `NFR-V2-008` | 証券発行バッチとの受渡し項目と責任分界を運用追補へ記載する。 |

## 8. 受入テスト範囲

最低限、次を含める。

- V1ゴールデン19件の主契約互換
- 特約なし、ADのみ、HIのみ、AD+HI
- AD年齢14・15・60・61歳
- AD保険金額100万円、1,000万円、1,100万円、2,000万円、上限超過
- AD特約額が主契約額以下・超過
- HI年齢14・15・60・61歳
- HI日額3,000円、5,000円、10,000円、その他
- 標準体と社医回付、一次・二次決裁
- 主契約承諾、延期、謝絶、失効、取下げ時の特約結果
- 一方の特約だけが謝絶または延期となるケース

すべての組合せの直積はV2の納期内試験対象外とし、未実施範囲を明示する。

## 9. 対象外

- 特約保険料・責任準備金計算
- 給付請求・支払査定
- 成立後の特約保全
- 特約を任意個数扱う汎用データモデル
- V1主契約プログラムの共通化、正規化、再構成
